Executive Summary Thekedar Connect is India's first hyperlocal contractor marketplace purpose-built for Tier-2 and Tier-3 cities. The platform bridges a critical gap: millions of property owners have no reliable way to discover, vet, or hire local contractors (thekedars), while skilled contractors have no digital channel to find and win leads beyond word-of-mouth. Unlike UrbanCompany which serves metro cities and direct labor, Thekedar Connect specifically connects customers with contractor businesses — civil contractors, renovation contractors, painting contractors, plumbing contractors, electrical contractors, tile contractors, false ceiling contractors, CCTV contractors, aluminium contractors, and interior contractors — who manage entire projects and labor teams. The Problem Property owners in Tier-2/3 cities discover contractors only via referrals, which is slow, unreliable, and geographically limited No verified portfolio, no transparent pricing, no accountability after handshake deals Contractors lose up to 40% potential business to competitors with better social networks No digital record of work history makes scaling a contracting business nearly impossible Fraud and fly-by-night operators cause massive financial losses to homeowners The Solution A mobile-first Flutter application with role-based login (Customer + Contractor), backed by Supabase and a micro-credit economy designed for the price sensitivity of Indian Tier-2/3 markets. Contractors pay small credits (₹2–₹15 per lead) to unlock project details, making the platform affordable and accessible. Market Research & Opportunity 2.1 Indian Construction Industry Overview India's construction sector is the second-largest employer in the country, employing over 60 million people. The residential construction market alone is valued at ₹7.8 lakh crore (2024) and is growing at a CAGR of 8.5%. PMAY (Pradhan Mantri Awas Yojana) is adding over 2.95 crore homes, creating enormous contractor demand in non-metro cities. The renovation and interior market is equally large. India has an estimated 26 crore urban housing units, with an average renovation cycle of 8–12 years. At an average spend of ₹2–5 lakh per renovation, this represents a ₹5–13 lakh crore latent opportunity. 2.2 The Contractor Discovery Problem Current contractor discovery methods in India are severely fragmented: WhatsApp groups and local referral networks (most common, highly limited reach) Hardware store notice boards and recommendations JustDial listings (unverified, outdated, metro-centric) Social media (Instagram reels for interior contractors only) Facebook local groups (unreliable, no verification) Newspaper classifieds (dying, low response) No platform today offers: verified contractor profiles, portfolio showcase, transparent reviews, project-based lead matching, and a trust layer for Tier-2/3 city contractors. 2.3 Contractor Behavior Research 80% of contractor income comes from repeat customers and referrals Average Indian contractor manages 3–8 projects simultaneously Contractors are WhatsApp-native, not email or web users Price sensitivity is extreme — monthly subscriptions above ₹500 see <5% conversion Trust and reputation are the #1 growth lever for contractor businesses Most contractors have smartphones but limited digital literacy beyond WhatsApp Contractors in Tier-2/3 cities earn ₹40,000–₹3,00,000/month depending on scale 2.4 Customer Behavior Research Tier-2/3 homeowners spend 3–8 weeks finding a reliable contractor 60% rely entirely on personal referrals — a broken system for first-time homeowners Primary fear: contractor taking advance and disappearing (45% of complaints) Secondary fear: substandard work with no accountability Product Architecture 4.1 System Overview The platform consists of three components deployed on a Supabase backend with Flutter frontends: Customer + Contractor App: Single Flutter app with role-based login (MVP strategy) Admin Panel: Separate React/Next.js web application Backend: Supabase (Auth + PostgreSQL + Storage + Realtime) Notifications: Firebase Cloud Messaging (FCM) Payments: Razorpay payment gateway Maps: Google Maps Platform 4.2 High-Level Architecture Tech Stack Summary Frontend: Flutter 3.x + Riverpod (State) + GoRouter (Navigation) Backend: Supabase (BaaS) — Auth, PostgreSQL, Storage, Realtime, Edge Functions Database: PostgreSQL 15 with PostGIS for geospatial queries Storage: Supabase Storage (S3-compatible) for images/videos/documents Push Notifications: Firebase Cloud Messaging (FCM) Payments: Razorpay (UPI, Cards, NetBanking, Wallets) Maps: Google Maps SDK for Flutter + Places API + Geocoding API Analytics: Mixpanel / Firebase Analytics Admin Panel: Next.js + Tailwind CSS + Supabase client 4.3 User Roles & Access Role Access Level Key Permissions Customer Mobile App — Customer Flow Post projects, browse contractors, chat, review Contractor Mobile App — Contractor Flow Browse leads, apply with credits, manage portfolio Admin Web Admin Panel only Full CRUD on all entities, moderation, analytics Super Admin Web Admin Panel + API access All admin permissions + financial reports + system config 4.4 MVP Strategy: Single App, Dual Role For MVP, a single Flutter application handles both Customer and Contractor roles via role-based navigation post-login. This reduces development time by ~40% and allows faster iteration. The role is set during registration and stored in the user profile. GoRouter handles route guards based on role. Login/OTP screen shows role selection: 'I want to hire' vs 'I am a contractor' Post-login, GoRouter directs to role-specific home shell (BottomNavBar differs per role) Shared components: Chat, Profile, Notifications, Settings Role-specific components: Projects (Customer), Leads/Wallet (Contractor) 5. Supabase Architecture 10.1 Authentication Design Primary: Phone OTP via Supabase Auth (supabase.auth.signInWithOtp(phone: ...)) Secondary: Google OAuth via Supabase Auth (supabase.auth.signInWithOAuth(google)) Session management: Auto-refresh tokens handled by Supabase client User role stored in users table, checked post-auth 10.2 Row Level Security (RLS) Policies Key RLS Rules users: SELECT own row only. UPDATE own row only. No DELETE. contractors: SELECT all (for discovery). UPDATE own record only. projects: SELECT if status='active' OR owner. INSERT as customer. UPDATE/DELETE own. applications: SELECT own (customer sees all for project, contractor sees own). INSERT as contractor. credit_wallets: SELECT/UPDATE own wallet only. credit_transactions: SELECT own transactions. INSERT via Edge Function (service role). chat_rooms: SELECT if participant (customer_id OR contractor.user_id = auth.uid). messages: SELECT if in room. INSERT if in room. UPDATE own messages. reviews: SELECT all visible. INSERT as customer (one per project). UPDATE/DELETE own. portfolio_items: SELECT all. INSERT/UPDATE/DELETE as owning contractor. verification_requests: SELECT own. INSERT own. UPDATE via service role (admin). 10.3 Storage Buckets Bucket Access File Types Max Size avatars Public jpg, png, webp 2MB project-photos Public jpg, png, webp 5MB each portfolio-media Public jpg, png, webp, mp4 50MB (video), 5MB (image) verification-docs Private (admin only) jpg, png, pdf 5MB chat-attachments Authenticated participants only jpg, png, webp 10MB 10.4 Realtime Architecture (Chat) Supabase Realtime uses PostgreSQL logical replication. The Flutter app subscribes to the messages table filtered by room_id: Chat Realtime Code Pattern // Subscribe to messages in a room supabase.from('messages')   .stream(primaryKey: ['id'])   .eq('room_id', roomId)   .order('created_at')   .listen((data) { /* update UI */ });  // Also subscribe to project notifications supabase.from('applications')   .stream(primaryKey: ['id'])   .eq('project_id', projectId)   .listen((data) { /* new application alert */ }); 10.5 Edge Functions purchase-credits: Verifies Razorpay payment, credits wallet (runs as service role) unlock-lead: Deducts credits, unlocks project for contractor (atomic transaction) calculate-trust-score: Recalculates contractor trust score on review/verification change send-notification: Triggers FCM push via Firebase Admin SDK auto-close-projects: Cron job — closes projects 30 days after posting 11.
